## 1. Обзор проекта

**Valorant Tournament Platform** — это платформа для проведения любительских и полупрофессиональных турниров по Valorant в СНГ. Мы объединяем игроков, команды и организаторов, предоставляя инструменты для создания турниров, поиска скримов и отслеживания статистики.

**Ключевые особенности:**
*   Не социальная сеть: нет друзей, лайков, личных сообщений.
*   Фокус на киберспорт: турниры, скримы, командная статистика.
*   Честность: обязательная привязка Riot ID, модерация.

## 2. Технологический стек и Архитектура

Проект организован как **монорепозиторий** (Monorepo) с использованием `pnpm workspaces`.

### Структура репозитория
```
root/
├── apps/
│   ├── web/               # Основной веб-фронтенд (Vite + React)
│   └── desktop/           # Десктопное приложение (Electron)
├── packages/
│   └── shared/            # Общие типы, утилиты и конфиги
├── supabase/              # Миграции БД и конфиги Supabase
└── SKILLS/                # [AI Context] Правила и навыки для AI-ассистента
```

### Стек технологий
*   **Frontend (Web & Desktop Renderer):** React 18, TypeScript, Vite.
*   **Desktop Shell:** Electron.
*   **UI Framework:** Tailwind CSS, shadcn/ui (Radix UI).
*   **State Management:** TanStack Query (Server State), React Context (Auth).
*   **Forms:** React Hook Form + Zod.
*   **Routing:** React Router v6.
*   **Backend:** Supabase (PostgreSQL, Auth, Realtime, Storage).
*   **Icons:** Lucide React.
*   **Dates:** date-fns.

## 3. Спецификация (MVP)

**Цель MVP:** Рабочая платформа для проведения тестовых турниров и сбора фидбека.

### 3.1. Пользователи и Роли
*   **Игрок:** Базовые права, создание/вступление в команды, участие в турнирах.
*   **Капитан:** Управление составом (max 10 чел), регистрация на турниры.
*   **Тренер:** Права капитана (кроме удаления команды).
*   **Организатор:** Создатель турнира. Управление сеткой, ввод счетов.
*   **Админ:** Полный контроль (бан, правка данных, валюта).

### 3.2. Основные модули
1.  **Профиль:**
    *   Регистрация (Email/Pass).
    *   Привязка Riot ID (обязательно).
    *   Ранги, агенты, роли.
2.  **Команды:**
    *   CRUD команд.
    *   Приглашения и заявки.
    *   История матчей.
3.  **Турниры:**
    *   Форматы: Single Elimination, Double Elimination.
    *   Генерация сетки.
    *   Ручной ввод результатов организатором.
    *   Статусы: Регистрация, Идет, Завершен.
4.  **Скримы:**
    *   Поиск оппонентов для тренировок (без рейтинга).

### 3.3. Post-MVP (Планы)
*   Внутренняя валюта и магазин.
*   Автоматический ввод результатов (OCR/API).
*   Система уведомлений (расширенная).
*   Интеграция с Discord.

## 4. База данных и Realtime

Используется **PostgreSQL** (через Supabase).
Безопасность обеспечивается через **RLS (Row Level Security)**.

### Основные таблицы
*   `users`: Расширение стандартной таблицы `auth.users`.
*   `profiles`: Данные игрока (Riot ID, rank).
*   `teams`: Данные команд.
*   `team_members`: Связь игроков и команд (роли: captain, player, coach).
*   `tournaments`: Конфигурация турниров.
*   `tournament_participants`: Зарегистрированные команды.
*   `matches`: Матчи турниров и скримов.

### Realtime
Репликация включена для таблиц: `profiles`, `teams`, `team_members`, `team_invitations`, `matches`, `notifications`.
Фронтенд использует подписки Supabase для мгновенного обновления интерфейса.

## 5. Руководство разработчика (Contributing)

### Запуск проекта
Используется root `package.json` для управления всем монорепозиторием.

```bash
# Установка зависимостей
npm install

# Запуск режима разработки (Web + Desktop)
npm run dev

# Запуск только веб-версии
npm run dev:web

# Проверка типов (TypeScript)
npm run typecheck

# Линтинг
npm run lint
```

### Переменные окружения (.env)
Создайте `.env` в корне проекта:
```env
VITE_SUPABASE_URL=your_url
VITE_SUPABASE_ANON_KEY=your_key
```

### Стандарты кодирования
1.  **TypeScript:** Строгая типизация. Избегать `any`. Использовать типы из `packages/shared` или генерируемые из БД.
2.  **Компоненты:** PascalCase. Один файл = один компонент.
3.  **Стили:** Tailwind CSS. Использовать `cn()` для условных классов.
4.  **Стейт:** Использовать TanStack Query для данных с сервера.

### Работа с Git
*   Ветки: `feature/name`, `fix/name`.
*   PR в `develop` (или `main`, если так настроено).
*   Коммиты: Conventional Commits (`feat: ...`, `fix: ...`).
